The user-provided archive `tempelmeir destroff.zip` contains 3450 unique DAT instances internally
labelled `Instance pour le MLSCLSP Tempelmeier`.

Observed structural classes:

- 1050 × 10 items / 4 periods / 3 resources / 1 finished product;
- 1050 × 10 / 4 / 3 / 4;
- 600 × 40 / 16 / 6 / 2;
- 600 × 40 / 16 / 6 / 6;
- 150 × 100 / 16 / 10 / 15.

All Gozinto coefficients are binary. External-demand rows are exactly the first
`NB_PRODUITS_FINIS` products. Capacities are stationary in all 3450 files. Unit production time is
1 for every item, and source unit production cost is zero throughout the corpus.

## Resource membership

`CL_Produit<i>` is a resource-indexed setup-cost vector. A nonzero component is treated as the
explicit source signal that item `i` is processed on that resource. The corpus contains 1200 item
rows with an all-zero vector. 600 of those still have a positive scalar setup time. Because the DAT
format provides no independent resource identifier in these rows, v0.13.0 deliberately does not
invent one. Such items receive an empty production routing and are flagged in provenance metadata.

This is an explicit source-format ambiguity, not silently repaired data.

## BOM mapping

`Gozinto<i>[j] = 1` is interpreted as item `j` being a component required by parent item `i`, matching
the parent-to-component convention already used by the ecosystem converter
`AddComponentRequirement(parent, component, quantity)`.
