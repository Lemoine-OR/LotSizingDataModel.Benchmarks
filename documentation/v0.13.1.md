## Resource membership

`CL_Produit<i>` is a resource-indexed setup-cost vector. A nonzero component is treated as the
explicit source signal that item `i` is processed on that resource. The corpus contains 1200 item
rows with an all-zero vector. 600 of those still have a positive scalar setup time. Because the DAT
format provides no independent resource identifier in these rows, v0.13.0 deliberately does not
invent one. Such items receive an empty production routing and are flagged in provenance metadata.

This is an explicit source-format ambiguity, not silently repaired data.

## BOM mapping

`Gozinto<i>[j] = 1` is interpreted as item `j` being a component required by parent item `i`, matching
the parent-to-component convention already used by the ecosystem converter
`AddComponentRequirement(parent, component, quantity)`.

The failed v0.13.0 run exposed 1200 medium instances in which `CL_Produit29` is the all-zero setup-cost
vector. Treating nonzero setup cost as the only resource-membership signal therefore produced an empty
routing and `ROU006`.

This is now repaired from published Test Set C resource-assignment tables, not by inventing a resource.

For the 40-item / 6-resource families, the original benchmark documentation gives four complete operation-
resource maps:

- general / non-cyclic;
- general / cyclic;
- assembly / non-cyclic;
- assembly / cyclic.

The supplied source corpus contains all resource identities directly in `CL_Produit` except item 29.
For each of the 1200 affected instances, the other 39 nonzero resource signals match exactly one of the
published maps. Item 29 is assigned from that unique matching map. The semantic guard requires exactly
1200 such unique documented reconstructions and rejects any non-unique or off-pattern case.

The recovered item-29 resource is therefore source/literature constrained:

- general non-cyclic: resource E / 5;
- general cyclic: resource D / 4;
- assembly non-cyclic: resource E / 5;
- assembly cyclic: resource F / 6.
