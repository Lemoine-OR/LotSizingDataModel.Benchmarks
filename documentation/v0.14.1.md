## TEST source contract

All 120 source files satisfy exactly the same numeric token contract:

1. number of items;
2. number of periods;
3. `items × periods` item-major demand values;
4. `periods` machine capacities;
5. `items` triples:
   - fixed setup cost;
   - unit inventory holding cost;
   - unit capacity consumption / processing time.

This consumes every numeric token in every TEST file exactly.

The three classes are:

- TEST1–40: 50 items × 8 periods;
- TEST41–80: 20 items × 20 periods;
- TEST81–120: 8 items × 50 periods.

The source has no setup-time field, so canonical setup time is zero. It has no unit production-cost
field, so canonical unit production cost is zero.

## Excel result trust gate

The three Excel 5.0 workbooks are read with NPOI. Every numeric cell belonging to a row identified by
TEST1..TEST120 is preserved with workbook, sheet, row, column and nearest detected column header.

The workbooks contain multiple method labels such as `ABCX`, `ABCX20`, `ABCXexp`, `HEUR1`, etc.
v0.14.0 deliberately does not infer that every numeric cell is an objective value: timing and other
computational measurements may also be present. Therefore:

- workbook evidence is retained as `LITERATURE_WORKBOOK_RESULT_CELL`;
- no automatic `BEST_KNOWN` objective is chosen;
- no `VERIFIED_FEASIBLE` or `VERIFIED_PROVEN_OPTIMAL` status is granted without a complete solution
  certificate passed through LotSizingDataModel.Checker.

## v0.14.1 — BIFF5 reader repair

The first v0.14.0 field run demonstrated that the three historical workbooks are true Excel
5.0/7.0 BIFF5 files. NPOI/HSSF rejects these files with `OldExcelFormatException` because HSSF
supports BIFF8 but not BIFF5.

v0.14.1 removes NPOI completely and uses `ExcelDataReader`, whose binary reader explicitly supports
BIFF2, BIFF3, BIFF4, BIFF5 and BIFF8. On .NET 10 the reader registers
`CodePagesEncodingProvider` and uses Windows-1252 fallback encoding, as required for BIFF2–5 text.

The safety harness performs an actual read of `lot50.xls`, `lot20b.xls` and `lot8.xls` before
installation and requires the extracted evidence identities to be exactly `TEST1..TEST120`.
