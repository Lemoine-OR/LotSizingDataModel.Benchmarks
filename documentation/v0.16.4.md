# v0.16.4 — Global Benchmark Registry & Trust Catalogue

This release adds a cross-family registry without rewriting any canonical benchmark XML.

Expected canonical corpus:

- DJ2000: 176;
- STADTLER2003: 2100;
- SUERIE_CLSPL: 1291;
- TRIGEIRO1989: 751;
- TD1996: 3450;
- CATTRYSSE1990: 120.

Total: **7888 canonical instances**.

## Identity rule

Historical names never establish identity by themselves. Duplicate/genealogy relations are created
only from exact `SupplyChainFingerprint` equality over canonical LotSizingDataModel instances.

The Trigeiro `G30` / transformed `G30b` distinction becomes a permanent regression guard. The
registry requires exactly one authoritative `TRIGEIRO1989::G30` and forbids silent creation or merge
of `G30b`.

## Per-instance registry fields

The machine-readable registry contains:

- stable `global_instance_id`;
- benchmark family and subfamily/class;
- original instance id;
- canonical XML path and SHA-256;
- source provenance role and source SHA-256 where family metadata provides them;
- planning horizon, item/work-center quick facts, LSDM tags/classification when present in XML;
- exact canonical fingerprint;
- trust status;
- objective/reference value and lower bound where reconciled;
- complete-solution availability;
- Checker verification state;
- optimality status;
- literature source where known;
- exact duplicate cluster and genealogy status.

## v0.16.4 — Windows PowerShell 5.1 parser repair

The initial v0.16.0 package used three C#-style chained member calls split across physical lines.
Windows PowerShell 5.1 does not accept a new physical line beginning with `.Method(...)`.

The repaired package now computes intermediate values before invoking `ToUpperInvariant()` or
`ToLowerInvariant()`. It also removes the direct assignment from an `if/else` statement in the
registry builder, following the project's PowerShell 5.1 safety rules.

In addition, the installer itself parses every extracted package `.ps1` with the Windows PowerShell
parser before invoking the package's safety harness. A future syntax defect in the safety harness can
therefore no longer prevent the parser guard from running.


## v0.16.4 — canonical-root repair

The v0.16.1 semantic preflight discovered 2,642 XML files under `SUERIE_CLSPL` while the canonical
corpus is 1,291. The broad recursive discovery was therefore counting non-canonical materialized views
in addition to the canonical corpus.

`2,642 = 1,291 + 1,291 + 60` is consistent with the repository history: one canonical 1,291-instance
tree, a second organized/materialized 1,291-instance view, and the 60 repaired `datab/B+` source-side
instances used during reconciliation.

v0.16.4 removes root-wide recursive canonical discovery. A shared `CanonicalCorpus-v0.16.4.ps1`
defines explicit allowed roots for every family:

- `SUERIE_CLSPL\instances` — exactly 1,291 canonical XML;
- `TRIGEIRO1989\instances` — 751;
- `TD1996\instances` — 3,450;
- `CATTRYSSE1990\instances` — 120;
- the eight explicit Stadtler class `instances` roots — 2,100 total;
- DJ2000 uses an ordered set of explicit historical canonical layouts and accepts only a layout whose
  cardinality is exactly 176.

The same resolver is dot-sourced by both the safety harness and the production runner. There is no
second, independently implemented discovery algorithm.

The pack also generates `GLOBAL-CANONICAL-CORPUS-AUDIT-v0.16.4.csv`, which inventories XML found
outside the canonical roots. Those files remain untouched and are explicitly reported as excluded
views/evidence rather than silently ignored.


## v0.16.4 — PowerShell 5.1 Join-Path runtime repair

The v0.16.2 parser preflight passed but the shared canonical resolver failed at runtime when building
DJ phase-root arrays with commands written as `Join-Path ..., Join-Path ...`. In Windows PowerShell
5.1 the comma is bound to the first command and produces an `Object[]` for `ChildPath`.

v0.16.4 precomputes every phase path in a scalar variable and then constructs the array from variables.
The safety harness now includes a permanent runtime anti-pattern guard rejecting physical lines that
start a `Join-Path` command and end with a comma. This complements the parser guard because the original
construct is syntactically valid but semantically wrong in PowerShell 5.1.


## v0.16.4 — historical identifier namespace repair

The v0.16.3 dry-run successfully built all 7,888 rows before the machine validator found that a
historical Stadtler identifier (`G501120`) is reused across distinct subfamilies/classes.

The historical id remains unchanged. The global key is now scoped as
`family::subfamily::original_instance_id` when a subfamily exists, and as
`family::original_instance_id` otherwise.

`GLOBAL-HISTORICAL-ID-COLLISIONS-v0.16.4.csv` records every historical id reused within a family,
together with its subfamily, canonical XML path and fingerprint. Reused names are documentation
events, not duplicate-instance evidence.

The release also capitalizes the PowerShell 5.1 `Join-Path` array-binding failure: comma-separated
`Join-Path` expressions in a `-Candidates @(...)` array can bind an `Object[]` to `ChildPath`.
Candidate paths are now always pre-computed into scalar variables, and the safety harness guards the
specific anti-pattern.
