# v0.4.2 — complete Stadtler stabilization pack

This release is intentionally incremental and idempotent.

It does **not**:
- execute `start_ini.bat`;
- execute `TempelmeierConverter`;
- rerun `LotSizingDataModel.Checker.Cli`;
- rewrite any of the 2,100 canonical Stadtler XML files.

It validates and post-processes the already generated corpus.

## Permanent PowerShell 5.1 delivery rules

Every pack must pass:
1. Windows PowerShell parser validation;
2. `-NonInteractive` dry-run;
3. ASCII validation for `.ps1`;
4. alias-collision validation;
5. prohibition of `@($genericList)` for `Generic.List<T>`;
6. prohibition of ambiguous `.Replace([char], ...)` calls;
7. exact package-name validation;
8. no-generator/no-converter/no-checker-rerun guards for incremental packs;
9. corpus and reference-catalogue preconditions/postconditions.

## Corpus semantics

The 2,100 XML files are the **generated admissible universe** accepted by the eight upstream
Stadtler generators under the documented parameter domains.

The Excel solution workbooks define a **published-reference subset**. These concepts are deliberately
kept separate. An admissible generated instance is not claimed to have a published BKV merely because
it exists in the generated universe.

## Fingerprints

Canonical file manifests are explicit:
- exactly 2,100 Stadtler XML from the eight `*/instances` directories;
- exactly 1,291 CLSPL XML from the single top-level `SUERIE_CLSPL/instances` directory.

Two .NET processes calculate all fingerprints. Copies in `instances-with-reference` and organized
subsets are excluded.

## Literature

Previously extracted workbook CSVs are deduplicated. Official workbook rows are mapped by
official class plus the canonical seven-position Stadtler code. `classcm` remains a separate legacy
archive and is never silently promoted to an official ninth test set.

No row-order mapping is permitted.
