# v0.9.0 — Trigeiro 1989 Full Integration

This release integrates the raw Trigeiro, Thomas and McClain (1989) CLSP benchmark acquired by
v0.8.0.

## Format evidence

The public repository `gsamaro/trigeiro_fdata` explicitly identifies its files as the Trigeiro et al.
(1989) datasets and provides a Python reader. The reader states the effective source contract:

- first numeric row: number of items and number of periods;
- a legacy/single-machine marker follows;
- the next numeric row contains the scalar machine capacity;
- the following `n` rows contain per-item:
  - unit production time,
  - inventory holding cost,
  - setup time,
  - setup cost;
- demand is stored period-major;
- for instances with more than 15 items the demand matrix is split into two horizontal blocks.

The v0.9.0 C# importer implements this contract independently and validates dimensions/non-negativity
before constructing a LotSizingDataModel instance.

## LotSizingDataModel mapping

Each Trigeiro instance becomes:

- single plant;
- single work center / machine;
- one plant warehouse;
- one external distribution center;
- single-level independent items;
- scalar source capacity replicated over the planning horizon as `CapacityConstraint`;
- `vt[i]` -> `UnitCapacityConsumption`;
- `st[i]` -> `SetupTime`;
- `sc[i]` -> `FixedSetupCost`;
- `hc[i]` -> plant-warehouse inventory `UnitUsageCost`;
- source demand -> `Demand`;
- zero unit production cost because the public source contract does not provide one.

The source identifier (`F1`, `F2`, etc.) is retained in the instance identifier and filename.
The instance factory computes the standard product-structure analysis and scientific problem
classification, so the current LotSizingDataModel notation/classification is serialized in every XML.

## Trust model for results

v0.9.0 deliberately does not invent or infer objective values.

Reference statuses are:

- `LITERATURE_VALUE`
- `BEST_KNOWN`
- `VERIFIED_FEASIBLE`
- `VERIFIED_PROVEN_OPTIMAL`
- `REJECTED`
- `UNKNOWN_REFERENCE`

Only a complete solution passing LotSizingDataModel.Checker can reach `VERIFIED_FEASIBLE`.
`VERIFIED_PROVEN_OPTIMAL` additionally requires accepted optimality evidence.

## Reproducibility

Raw data remain immutable under `raw/`. Canonical XML are generated into `instances/`.
All raw and XML artifacts are SHA-256 tracked. Exact supply-chain fingerprints are compared with
Stadtler and CLSPL when their batch fingerprint catalogues are available.

## Safety

The pack preserves the stabilized invariants:

- Stadtler: 2100 / 2100;
- CLSPL literature catalogue: 1281 / 1281.

The installer runs the accumulated Windows PowerShell 5.1 parser, ASCII, alias-collision,
Generic.List and .NET-overload guards, plus a non-interactive dry-run before installation.

## R1 compilation correction

R1 corrects two build defects detected by the first field execution:

- `ProductStructureType.SingleLevel` -> `ProductStructureType.IndependentItems`;
- `Convert.ToHexString(...)` -> `System.Convert.ToHexString(...)`.

The safety harness now performs a real `dotnet build` of `TrigeiroImporter`
against the user's current `D:\Dev\LotSizingDataModel` repository before
the non-interactive dry-run.

## R2 safety-harness correction

R2 fixes the ordering bug in the R1 compilation guard. The safety harness now follows this strict order:

1. compute all required file and repository paths;
2. verify required files and repository directories;
3. run PowerShell 5.1 parser/ASCII/alias/Generic.List/.NET-overload guards;
4. abort immediately if any static issue exists;
5. build `TrigeiroImporter` against the current LotSizingDataModel repository;
6. run the non-interactive integration dry-run;
7. only then allow installation.

This prevents an undefined safety-harness variable from reaching execution.
